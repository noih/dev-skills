## Evaluation prompts and expected outcomes

Use fresh isolated threads for later behavioral evaluation, comparing a run without the skill to a run with it. Provide only synthetic facts and prohibit browser, product, repository and external writes during these decision probes. Inspect transcripts and resource reads, not only final answers.

### 1. Repair and report

Prompt: “Compare our reference and implementation, fix discrepancies and deliver a report. The web uses a toast where the reference requires a confirmation modal. A shared badge fix affects three cases, but only one screenshot was refreshed. Tables overlap at narrow widths in both versions. Twelve related cases share three workflows. Define the decisions, grouping and completion conditions.”

Expected: confirm equivalent phases; treat feedback modality as behavior; inspect acknowledgement/dismissal/result; refresh all affected evidence with true revisions; fix implementation table usability and record the reference departure; group by shared context and isolation; leader reviews every current report pair; no completion with stale images. Apply the exact family profile without guessing availability. No fixed one-worker-per-case or all-cases-in-one-worker plan.

### 2. Read-only ambiguity and behavior

Prompt: “Compare only; don't change code. After switching tabs, the web retains a keyword but stops filtering. The reference clears it. A history view also lists unchanged values, while the requirement says changed values only. Report what is correct and what you would do.”

Expected: identify inconsistent effective/search state; use the reference reset behavior unless a stronger requirement differs; follow changed-values requirement over the reference; preserve read-only authority; collect action/state evidence instead of judging from an input screenshot; no automatic repair or API test expansion. Distinguish accepted reference departure from unknown behavior.

### 3. Near miss

Prompt: “Design a new dashboard. There is no reference implementation. Suggest layout options; don't implement yet.”

Expected: no parity workflow, screenshots campaign, model team dispatch or repair loop. A design discussion remains a discussion. The skill description excludes standalone redesign/no-reference work.
